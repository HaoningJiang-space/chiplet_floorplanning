# 载板尺寸协同优化 v3：以参照布局为锚点、外层按长宽比二分、内层固定载板求解（运行前冻结，2026-11-17）

依据：cosize-v2 停止前已完成的 40 个任务（`results/cosize-v2`，代码 `c2efe56`，2026-11-17 由用户决定停止剩余消融）。

## 1. v2 的诊断（数据，不是推测）

- cosize 已完成 16 个任务，只有 6 个得到设计（Case1–5 的部分组合）。其余每轮 4 个场数选项的 MILP 都在 60 s 超时且**没有可行解**。
  例如 Case6–10 atp_wl：4 轮 × 4 选项 × 64 s ≈ 1024 s，FV 只有校准的 12–14 次。时间几乎全部花在无解的 MILP 上。
- 超时（time_limit）被当作不可行处理：放宽 0.25 K 后从头再解，结果仍然超时。
- 根本原因：联合 MILP 同时包含"最小化面积 + 硬热约束 J ≤ −margin + 全部芯粒对的 big-M"，大案例找不到第一个可行解；而且没有可行的起始解。
- 对照：固定载板的子问题可解。
  - [8 方向门槛](polygon-distance-plan.md)：固定原载板时，热启动的 MILP 10/10 给出解；
  - fixed_aspect：在固定载板上搜索，在 Case1、6、7、10 都找到了缩小后的设计。
- 另一个事实：在 atp_wl 参照下，fixed_aspect 在**原载板**上多次找不到满足 L ≤ L_ref 的布局（Case5、6、8 wl）。
  ATPlace 的线长优化在这些例子上比我们的布局搜索强。但 ATPlace 的布局本身**已知满足两项上限**（T = T_ref，L = L_ref），v2 没有利用它。

## 2. 方法（`placement/cosize.py: anchored`）

问题不变：最便宜的载板（`cost.interposer_cost`），上面存在合法布局，满足每芯粒 FV 峰温 ≤ T_ref 且逐引脚长度 ≤ L_ref。

1. **锚点。** 参照布局在原载板上是已知可行点，用 1 次 FV 复核：峰温与存档 T_ref 之差 ≤ 1e-6 K，长度与 L_ref 之差 ≤ 1e-9 m，否则报 `reproduction_mismatch` 并停止。
   原载板可制造时，锚点就是初始最优解。所以每个方法的结果都不差于原载板，搜索失败只表示"没有改进"。
2. **外层：按长宽比二分。** 长宽比集合 A = {1/3, 1/2, 2/3, 1, 3/2, 2, 3}，再加原载板长宽比，共 8 族。
   - 同一长宽比下，载板等比放大不会减少所需曝光场数，所以成本随尺度单调。
   - 每族在尺度上二分 5 步：下界为芯粒总面积；上界为成本严格低于锚点成本的最大尺度（原载板不可制造时，取 3.3 倍掩模版限内的最大尺度），且面积不超过原载板面积 × 1.25²。
   - 结果取所有族认证设计中最便宜的一个。
3. **内层：固定载板求解。** 每个试探载板：
   - 先解轴向 MILP，再解 8 方向 MILP，后者以前者的解热启动；
   - 目标为最小化代理峰温，约束为聚类线长 ≤ 预算，并加逐引脚长度切割（至多 3 次）；
   - MILP 起始解：本族上一个认证布局（没有时用锚点），按比例映射到新载板后，用保持相对关系的 LP 合法化；
   - 用精确 FV 的 SLP 链（length 模式，至多 12 步）认证。认证通过，尺度上界下移；不通过，下界上移。
   - **没有裕量闭环**：内层直接最小化代理值，只用 FV 判定通过与否。v2 中由裕量引起的不可行问题不再存在。
4. **并行。** 8 族各占一个进程，Gurobi 每进程 2 线程。代理只校准一次，在父进程完成。
   FV 预算 1000 次：先扣除校准和锚点，剩余均分给 8 族；每条认证链按剩余预算截断。

## 3. 比较方法（同一代码、同一锚点、种子 2、1000 次 FV、MILP 每次 60 s）

- **cosize**：如上。
- **fixed_aspect**（主比较对手，"先定尺寸再布局"）：原长宽比、面积二分，每个尺寸用 relation_space 搜索（实现与 v2 相同）。
  唯一改动：第 0 步（面积系数 1.0，即原载板）直接由锚点认证，不消耗该步的 FV 份额。这使两方法的起点相同。
- **cosize_blind**（热信息消融）：外层相同，内层改为最小化线长（无代理）。
- **cosize_axial**（表示消融）：外层相同，内层只用轴向距离。

组合：atp_wl 为 Case1–10，atp_cool 为 Case1–7。Case8 atp_cool 待 ATPlace v3 完成 FV 评分后按同一协议追加；Case9、10 没有该参照。
参照布局来自 moe 上的 `compare/merged-v1/CaseN/<label>/layout.json`，即 `atplace-compare-rsg4-v2` 的同一批文件。

## 4. 判定（沿用 v2 冻结规则，`tools/cosize_compare.py`）

- 每个组合比较双方认证设计中最便宜的成本：≤ 0.95 倍为胜，≥ 1.05 倍为负。
- **有效**：胜 ≥ 40% 且负 ≤ 10%；**无效**：负 ≥ 25% 或胜 < 15%；其余为部分有效。
- 分母为冻结的组合清单，缺失的组合也计入。
- 由于锚点的存在，双方都至少有原载板的成本（原载板可制造时），"只有一方有解"的情况只会出现在原载板不可制造的 Case2、4、9。
- 另报告：
  - 相对原载板的节省；
  - 18 组成本参数下胜负是否保持；
  - FV 次数、墙钟时间、曝光场选项的变化。

## 7. 959f878 试跑结果（不计入判定）与 v3.1 修订（修订后、运行前写定）

### 试跑（`results/cosize-v3-pilot`，只跑了 cosize）

- **锚点复现：** Case1 cool 的 J = −2.4e-12 K，Case6 wl 的 J = 8.5e-14 K，长度一致。存档参照可用。
- **Case1 atp_cool：** 用时 434 s，145 次 FV。找到 60.3 × 20.1 mm（长宽比 3）的设计，成本 $123.5，原载板为 $253.9。
- **Case6 atp_wl：**
  - 用时 495 s，35 次 FV，最终只剩锚点；
  - 各族第一次试探就失败，随即整族放弃；
  - 失败的直接原因是线长：MILP 的布局 J ≈ −19 K，但长度 39.6 m，超过预算 29.6 m；
  - 由锚点映射得到的起点没有被单独认证。
- **Gurobi 状态 4（INF_OR_UNBD）：** 本模型的目标有下界，所以这一状态等同于不可行，但之前被记为普通失败。

### 修订（依据 [审阅](cosize-v3-first-principles-review.md) 与上述试跑；协议记为 cosize-v3.1）

1. **共用锚点复核（`verify_anchor`）。**
   - 所有方法用同一次 FV 复核，计入预算；
   - 保存逐芯粒实测 J、长度与合法性；不一致时所有方法同样退出；
   - fixed_aspect 第 0 步使用原载板本身，不再向上取整到网格。
2. **连续初始化。**
   - 每个试探载板先认证"至今最小认证布局按比例映射后合法化"的起点；SLP 链即保持拓扑的局部热与线长修复；
   - 起点失败后，才用 MILP 生成新拓扑；
   - 求解器无解不会丢掉起点；所有认证候选都保留；
   - fixed_aspect 在新尺寸上同样把这一起点交给 relation_space。
3. **失败状态分三类：** certified / not_found / proven_infeasible。
   - 只有 MILP 不可行（只含几何、聚类线长松弛和有效切割；状态为 infeasible 或 4）才能结束该族；
   - 理由：同一长宽比下更小的载板可以放进当前载板，所以同样不可行；
   - 其余失败只记录，搜索继续。
4. **外层候选。**
   - 每族的试探面积由两部分组成：上界与下界之间等分的 4 个点，以及成本曲线上每个大于 2% 的台阶之前的最大面积（曝光场数、基板档位）。从大到小试，至多 8 个；
   - 之后在"最小认证面积"与"其下最大失败面积"之间至多再二分 2 次；
   - 这是有限候选搜索，不报告可行域边界。
5. **资源约束。**
   - 每个试探载板的 MILP 共用一个总时限（`--size-s 120`），轴向、8 方向和切割都在其内；
   - 记录 MILP 时间、状态和 workers/threads；
   - cosize 为 8 族进程 × 2 线程；fixed_aspect 与 relation_space 对照用 16 个 FV 进程。
6. **预算前置：** 预算 0 时不做 FV；预算不够校准时，先报告停止，再决定是否校准。
7. **比较器。**
   - 有组合缺失时判定为 `incomplete`，不提前宣布结论；
   - 协议、案例哈希、锚点哈希、T_ref 或 L_ref 不一致的两次运行记为 `unpaired`，不参与配对。

### 有界对照（只在两个试跑例上）

**cosize_rs**：候选载板、起点和 FV 预算与 cosize 相同，只把新拓扑一步换成 relation_space。

- 多长宽比的两种内层都优于 fixed_aspect：收益主要来自形状和尺寸自由度。
- 代理内层在相同候选和起点下更好：才支持代理搜索带来额外价值。

## 8. v3.1 试跑结果（`results/cosize-v31-pilot2`，代码 `33ad191`，不计入判定）与 v3.2 修订

| 例 | cosize | cosize_rs | fixed_aspect | 原载板 |
|---|---|---|---|---|
| Case1 atp_cool | **$131.4**（20.5 × 61.3），246 s，177 FV | $251.4（41.9²），273 s，992 FV | $171.6（38.0²），199 s，830 FV | $253.9（42²） |
| Case6 atp_wl | **$363.9**（43.9 × 47.5），628 s，200 FV | 未完成即停止（预算缺陷，见下） | $677.7（49.9 × 54.0，**比原载板贵**），950 s，831 FV | $616.0（49 × 53） |

- **锚点复现正确：** 两例的 |J| 都小于 1e-11 K。
- **认证主要来自"起点"阶段：** cosize 的大多数认证设计来自"上一认证布局映射后用 SLP 局部修复"，MILP 只在没有起点时提供新拓扑。
  Case6 上 MILP 多数在时限内没有给出解，说明连续延拓才是主要的候选来源。
- 发现三个缺陷，均在正式运行前修复：
  1. **fixed_aspect 锚点判定：** Case6 锚点 J = 8.5e-14 K，在复核容差内，但基线用 J ≤ 0 判为失败，随后转向更大的尺寸，因此结果比原载板还贵。修复后，复核通过的锚点直接作为认证结果。
  2. **cosize_rs 预算：** relation_space 在每族第一个尺寸上就用完整族的份额（约 141 次 FV），后续尺寸无法试探。修复后每个计划内的试探最多分到等额份额。
     另外，没有合法起点时 relation_space 会抛出异常，现记为 not_found，搜索继续（复核 `f3f8494` 的 P1）。
  3. **细化缺失：** 一族的试探全部通过时（如 Case1 长宽比 3），原实现不再往更小的面积细化；现以芯粒总面积为下界继续二分。
- **比较器（复核 `f3f8494` 的两个 P2）：**
  - 重定价时，复核通过的锚点（原载板）始终保留在候选池中；
  - 配对前要求两次运行都有 seed 与 fv_budget，且两项相同，否则判为 unpaired。

以上修订记为协议 **cosize-v3.2**，其余同 v3.1。
