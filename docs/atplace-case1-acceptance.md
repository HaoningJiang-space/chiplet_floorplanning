# Case1 小步验收：端口方向进入目标，热模型响应几何移动

本项接通了**源 pin 坐标 → 合法布局/旋转 → 总 pin Manhattan 长度 → 简化热评估**。
这里只验收三个预先指定的布局，没有优化器或算法胜负比较。原 R3 文件及结果未改。

## 输入与模型

输入来自 ATPlace `fe3dbfdaf78dc0ddeac3a2cfc3a85ff0971f88df` 的 Case1，复用已核验的
[导入记录](evidence/atplace-import.json)：42 × 42 mm 载板、6 个芯粒、780 W、
3168 条两端网络、6336 个 pin。按源百分比偏移及源芯粒尺寸转换坐标，以芯粒中心
逆时针旋转，不将源 pin 替换为中心。每条源网络等权计入总和，重复连接不合并。

主互连量为 `Σ_net (|x1-x2|+|y1-y2|)`，以 m 报告总长度；几十米是数千条短连接
的总和，不是一条线的长度。它是两端 pin 的几何下界，尚未加入绕障、拥塞或 RC。
源 pin 的 `B` 方向不强行解释成时钟/数据，因此热输入保留全部端口，但电气
`links` 仍为空；时序没有被接通。此量不能与 R3 的需求加权平均中心距离直接比数值。

为隔离接口工作，热模型使用已有 TAP-family 八层 FV 材料参数，改用源 42 × 42 mm
载板；均匀功率覆盖源芯粒全矩形，没有添加外部 bump ring。声明固定 100 × 100 mm
扩散板、200 × 200 mm 散热器、45°C 环境、顶部 h=2777.7778 W/(m²K)，其余外表面
绝热。1 mm 最小芯粒间隙是本项显式研究选择，不来自那三个源输入文件。原始输入、
层叠、边界与三个候选在求解前保存到本地 plan/case 文件。

这是**共同简化模型上的基准适配**，不复现 ATPlace 原文/native ATSim 的温度，
也不将输入功率当作本轮实测。不能用同矩阵求解一致性推断真实封装精度。

## 三个固定布局与验收结果

基准中心（mm）为 CPU (7,29)、GPU0 (10,10)、GPU1 (30,10)、三个 HBM 分别
(19,29)、(29,29)、(38,29)，初始方向均为 0°。后两例各自只改动基准中的一项。

| 布局 | 总 pin 距离 m | 相对基准距离变化 | 峰温 °C | 相对基准峰温变化 K |
| --- | ---: | ---: | ---: | ---: |
| 基准 | 73.840208806 | 0 | 107.450477 | 0 |
| CPU 原地旋转 180° | 74.688592947 | +1.148946% | 107.450477 | 0 |
| GPU0 向 x、y 各移动 1 mm | 72.404992806 | -1.943678% | 108.638136 | +1.187659 |

- 全部布局满足源载板边界、不重叠和声明的 1 mm 间隙；每例保留 6336 个端口。
- Decimal 中心/偏移变换与生产 `Die.point()` 下左角变换逐 pin 对照，最大坐标差
  约 1.42e-14 mm；总距离独立累加一致。这是坐标实现检查，不是物理精度要求。
- 每例映射 780 W，HiTS 数值准入通过，能量收支误差绝对值不超过 2.81e-7 W。
- CPU 是均匀材料/均匀功率方形芯粒。原地 180° 后独立装配的热算子及功率向量
  完全相同，因此复用温度场，但重新计算 pin 长度；中心距离总和仍为 83.776 m。
  最终三个完整方向状态使用 **2 次新热求解、1 次热缓存命中**，没有合并 pin 目标。
- GPU 平移同时改变 pin 长度和热结果：连线下界缩短而峰温升高。这说明模型表达了
  一个真实的几何权衡机制，但**不是优化收益，也不是热—时序最优排序反转的证据**。

完整紧凑证据见 [JSON](evidence/atplace-case1-acceptance.json)。最终三个布局运行于
`results/atplace-case1-pin-acceptance-v3`，此前两个版本各三次直接求解单独保留。
开发直接求解也得到旋转温度不变；最终缓存检查独立装配算子，不冒充一次新求解。代码以证据中
LF-normalized 哈希绑定，`code_base_commit` 只表示开发基点，不冒充新文件所在提交。
324 项单元测试通过，复用本次通过的 two-chiplets CLI（生产入口未改）；新增五项
检查覆盖手算四向旋转、整体平移、源网络重复计数、边界/间隙、生产端口变换与
温度缓存不覆盖旋转后的 pin 目标。选择 180° 的固定诊断是为了直接检验旧热键的
等价类风险；90°/270° 的坐标变换另有手算检查。

复现：

```powershell
python tools/validate_atplace_case1.py --input results/physical-calibration/atplace-import-v1/Case1.json --hits ../HiTS --output results/atplace-case1-new
```

## 裁决与下一项

**通过范围：**源 pin 几何与声明的稳态热评估链，能够保留方向带来的互连变化和
移动带来的热变化。真实布线/电气时序闭环、优化算法与大案例效果仍未验收。

这次验收直接约束下一项算法修改：**布局状态不能按热等价类合并**。CPU 0°/180°
热等价但 pin 目标不等价；不能把 R3 的 `rotation % 180` 全局去重规则照搬过来。
现已分别维护完整四向布局状态与可复用的热查询，在同一温度缓存值下重新计算 pin
目标，并以不具有 180° pin 对称性的手算例验证。缓存仅适用于本适配器的固定均匀
材料/功率模型，不能泛化到非均匀功率块。下一项再做一个种子的有界结构搜索比较；
主比较阈值、查询/非热评估成本及基线需在正式运行前声明。尚不扩展到 20/61 个芯粒。
