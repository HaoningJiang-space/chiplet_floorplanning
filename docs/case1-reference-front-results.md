# Case1：叠加热代理诊断与参考前沿

2026-11-13，eex005，单种子 2026111300，24 进程。输入 Case1.json 哈希 `f2d55207…` 与全部历史冻结计划一致；
gap 1 mm，左下角 1 mm 网格，FV 64 网格配方与历史逐项相同（519 个历史布局峰温差 ≤1.6e-8 K）。
证据：[case1-reference-front-v1.json](evidence/case1-reference-front-v1.json)；原始布局在 eex005 `results/`。

## 1. 为什么换做法

一次精确 FV 评价约 0.25 s；24 进程约 125 次/s。历史各阶段每臂 16 次查询相当于约 4 s 计算，
却在比较 0.3 K 量级差异。本页把预算换成真实算力，先求同一模型的参考前沿，再判断算法差异是否有意义。

## 2. 叠加代理是否可以替代 FV

物理依据：材料固定时 Aθ=b 对热源线性；但芯粒移动会移动高导热岛（A 改变），且载板边界破坏平移不变。
代理用每个芯粒单独置于放大载板中心的 FV 响应平移相加，并未包含这两项。1000 个构造随机合法布局：

| 指标 | 结果 |
| --- | --- |
| 排序 | Spearman 0.965，Kendall 0.843，最冷 5% 重合 0.88，FV 最冷布局在代理中排名第 1 |
| 误差 | 平均偏高 1.76 K，标准差 0.74 K，去均值后最大 1.94 K |
| 速度 | 单核 8 ms/布局；FV 24 进程 1000 布局 8 s |

裁决：代理误差大于此前比较的差异，**不能作为结果温度**；Case1 直接用精确 FV 搜索。代理只留作更大案例的预筛。

## 3. 参考前沿

方法：96 个随机合法起点 + 96 个只用精确 pin 长度下降（无热成本）的起点，然后批量 Pareto 局部搜索
（平移 1/2/4/8 mm、转向、交换、按伙伴 pin 中位数的单芯粒精确长度移动），每代 96 个新布局全部 FV 评价。
预算 20000 个不同布局（12844 个不同热问题），总耗时 236 s。主指标与反向指标都取同一实际布局。

v1 的预算单位是布局数，不是 FV 求解数，且初始集合先评价、后检查额度（本次初始 192 个均不重复，
总数恰为 20000，没有超额）。外部审查（2026-11-13）指出后，`pareto_search` 已改为以**不同 FV 求解数**为
单位，并从初始化起去重和限额；之后的公平比较一律使用新单位。同一审查指出的单芯粒长度移动包含
同芯粒网络的问题已修复；Case1 没有同芯粒网络，本页结果不受影响。审查独立重算 6 个代表布局，
温差最大约 6.4e-13 K，pin 长度一致。eex005 上本次 2 万布局的原始文件 `layouts.npz` 被我误删，
提交的证据（前沿 199 点与全部代表布局）完整；需要时在 `1a2738d` 用 `tools/replay_at_commit.py` 重跑恢复。

## 4. 能说什么，不能说什么

- 能说：在同一热模型、同一距离下界和同一必要容量筛查下，历史各阶段远未接近可达前沿；
  紧预算下可同时降温约 0.55 K（对参考）并缩短 25% 距离。此前 16 查询的算子差异不能代表算法质量。
- 不能说：这是全局最优，或新方法在相同小预算下优于旧方法。这是 2 万次评价的近似参考前沿，单种子；
  距离仍是两端 pin 的 Manhattan 下界，不是布线长度、时序或实测温度。
- 下一步：以该前沿为参照，按相同算力比较方法（离前沿的差距），并扩展到 Case2–10；
  在更密的案例中先检查必要容量筛查是否变为活跃，需要时再移植到新核心。
