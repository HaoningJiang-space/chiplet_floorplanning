# 从物理方程到布局决策：当前问题与修正

分析起点：2026-11-13 fetch 成功，远端与本地均为 `50185da8ce4c9ff5b94922411627e908def39b5e`。
本页围绕已经观察到的失效机制，不把算法推进重新变成精度校准工程。

## 1. 到底在解什么物理问题

令 x 表示芯粒的中心、尺寸和朝向。当前模型是固定功耗、线性各向同性导热：

\[
-\nabla\cdot(k(x,\mathbf r)\nabla T)=q(x,\mathbf r),\qquad
-k\nabla T\cdot n=h(T-T_a)\quad\text{在散热器顶面}.
\]

侧面和底面绝热，层间热阻串联；有面接触热阻时温差满足
\(\Delta T=R''q''\)，其中 \(R''\) 为 m² K/W、\(q''\) 为 W/m²。
有限体积离散得到 \(A(x)\theta=b(x)\)，\(\theta=T-T_a\)，A 单位 W/K，b 单位 W。
正热导、相反方向共享同一导热面、明确的外部散热边界保证守恒和被动导热。

780 W 总功率从唯一顶面离开。积分守恒要求
\(h\int_{A_{top}}(T-T_a)dA=780\)，所以外表面均温恒为
\(45+780\times0.009=52.02\) °C。**位置优化不会降低总功耗或改变这个均温，
它改变的是热源分布、局部扩散阻力和峰温。** 不能用这个均温替代芯粒结温。

Case1 芯粒面积总计 1080 mm²、载体 1764 mm²，面积占比约 61.22%；CPU/GPU/HBM
功率密度分别约 0.729/0.926/0.260 W/mm²。这些量可解释为何关注 GPU，但温度也依赖
邻接、材料、热源面积及边界，不能把功率密度或 GPU 中心间距当温度目标。
这一建模边界与 [HotSpot 官方说明](https://lava.cs.virginia.edu/hotspot/)强调的
“布局与散热路径共同决定温度、功率不能直接替代温度”一致；这里仍使用自身 FV 方程，
不据此宣称 HotSpot 的验证结论自动转移到本项目。

## 2. 为什么朝向改善很大，却没有额外降温

对于均匀发热、各向同性的刚体芯粒，若命名物理矩形边界不变，则 k 和 q 都不变，
故 A、b 不变，温度不变。正方形四向转动、矩形半转就是这种情况。

源 pin 的世界坐标为 \(p_{i\alpha}=c_i+R(\phi_i)o_{i\alpha}\)，距离目标为
\(L=\sum_{e=(i\alpha,j\beta)}\|p_{i\alpha}-p_{j\beta}\|_1\)。朝向改变 offsets
的世界坐标，因此可显著改变 L。上一轮 B 的 72.597→38.228 m 正来自这种独立自由度。
它降低互连距离预算的占用，不构成热优化。对非均匀功率图、方向性材料或不同
安装界面的器件，这个热等价规则不再自动成立。

这里要区分**单个布局的温度不变**与**约束内最冷布局改变**：某个已求得的冷几何
原先因 L>L0 被排除，修复后可以进入可行集合，约束内最优温度就能降低。这种收益
来自可行集合扩大，不是同一几何被旋转“冷却”。Chat 本轮独立检查历史 B 时找到了
row 40：102.919524°C，原 L=81.489902 m，修复 L=60.185154 m。本地精确核对通过，
无需新热求解，已比上一轮局部最好点冷 0.595688 K。

位置变化则同时改变 A 和 b。即使局部可微，也有
\(d\theta=A^{-1}(db-dA\,\theta)\)。只考虑源移动、忽略随芯粒移动的高导热材料，
或者假设“更远一定更冷”，都不能从该方程推出。本轮选择实际热求解反馈，不引入
未经验证的距离—温度代理；有限步长搜索也不宣称满足连续优化的收敛定理。

## 3. 实验当前缺少哪种证据

上一轮修复后的全部 25 个候选 L 范围为 **35.412435–55.880993 m**，而 L0 是
73.840209 m，最小余量仍达 **17.959216 m**。因此该邻域中距离约束完全不活跃。
原朝向 4 个不满足预算，修复后全通过，但两组都很早看到了相同最冷几何；主指标
持平有明确机制，不是热求解器失灵。该实验只证明方向冗余可以消除，尚未证明
热—互连预算之间存在迫使算法取舍的紧张约束。

修正：保留原 L0/T0 和所有负结果，直接报告候选长度范围、最小余量、拒绝数、
完整联合点和预算轨迹；不根据观察结果缩紧 L0 制造冲突。今后研究紧约束时必须
依据独立设计要求预先指定新实验，不能把这次结果追认为紧约束研究。

固定 25 个候选的消融有清楚的因果范围，但它没有“得到更好位置后继续探索”的反馈。
修正：保持刚体移动、pins 修复和物理条件相同，两组都允许多步扩展，单独比较
父代选择是否使用实际温度；共同起点、缓存、阈值、种子和热预算必须相同。
这是 [Chat 完整复核](atplace-case1-orientation-review.md) 对原方案的重要修正，避免
把“多步能力”与“温度引导”混为一个因素。

进一步修正共同基线：对同一 Case1 名义模型的 A–F 和上一轮 orientation 档案进行
一次统一修复。528 条保存行去重为 246 个完整输入，关联 225 个已求解热几何，
修复后保留 448 个完整联合状态。88 个原超预算输入恢复距离可行性，492 次原/修复
必要容量检查全部通过。主已知参考更新为 **102.919524°C / 60.185154 m**；反向参考为
**106.038489°C / 35.014737 m**，后者来自历史 C row 24，是另一个布局。
37 个输入即使修复后仍超过 L0，所以“距离约束不活跃”只适用于前述 25 点邻域。
这一步 0 次新增热查询，属于历史档案利用；不能冒充后续在线温度反馈的收益。
在线实验的共同起点严格只用 B/D repaired，其余历史响应只作为缓存，历史最强点
单列为参考线。仅实际生成、通过准入的候选才能进入本轮搜索轨迹。

## 4. 计算瓶颈可以直接修，不需要新的物理假设

上一轮 25 个修复候选准备耗时约 8.829 s，热评估约 6.814 s。
每转一个芯粒仍重算所有 3168 条 net，共每布局 13 次全局 pin 计算。
但一个芯粒 i 变化时只有关联集合 E(i) 会变，严格有
\(L'=L-\sum_{e\in E(i)}\ell_e+\sum_{e\in E(i)}\ell'_e\)。

新增精确 incident-net 更新：保留 Decimal 坐标、源顺序、角度顺序和原平局规则；
同芯粒双端 net 只计一次，但两个端点均旋转；不关联的 net 原值复用。最后仍做一次
完整 pin 重算，并将真实端点交给原必要布线检查。每布局 net 长度计算从 41184 次
降到 21120 次，输出应逐项等价。这是实现优化，不更换算法目标。
历史冻结实现保持可回放，新实现通过全部 27 个已有 B/D 输入逐项比较后再进入搜索。

已完成验收：27/27 的姿态、完整热/布局身份、Decimal 距离、逐步朝向选择和必要容量
结果完全一致，0 次新热查询。长度计算总量 1111968→570240（减少 48.72%），
单次本地计时 11.155→2.121 s（新方法包含 0.090 s 的源索引初始化），约 5.26 倍。
这是一次本地计时观察，不是跨机器性能保证；精确等价和确定的工作量减少才是验收依据。
373 项测试及两芯粒 CLI 通过。[完整证据](evidence/atplace-case1-incremental-pins-v1.json)。
依 Chat 建议又覆盖 246 个历史完整状态和冻结池中未包含的输入，共 **255 个不同输入**：
每次中间选择、最终姿态、完整距离和必要容量全部与旧实现一致，仍为 0 次新热查询。
[历史等价证据](evidence/atplace-case1-incremental-history-v1.json)。加入多步父代实验后
376 项测试通过，其中控制组在替换温度响应后仍生成完全相同的候选轨迹。

## 5. 仍未解决、且不能靠改名掩盖的部分

| 问题 | 当前事实 | 正确处理 |
| --- | --- | --- |
| 真实 Pad 与布线 | ATPlace 源 pins 和理想资源下的必要容量，不含制造 bump、via/track 分配和真实回流路径 | 保留前置拒绝检查与明确范围；不宣称详细布通，不虚构 Pad 参数 |
| 热—时序耦合 | 此 Case1 的 links 为空，电阻电容占位为 0，没有温度相关延迟、泄漏或 PHY 工作点 | 称为固定功率下的热—互连几何优化；真实时序闭合需要单独接通接口数据，当前没有完成 |
| 边界可靠性 | 名义边界是研究假设，先前弱冷却/接触热阻场景使绝对 T0 失效 | 不把名义解推广为真实封装签核；当前不再扩大校准活动 |
| 泛化和最优性 | 一例、一个种子、有界预算、历史 warm-start | 只给局部证据，保留未探索部分；预算到达不是局部或全局最优证明 |

解决当前算法问题不要求先假装解决以上缺口。推进顺序是精确计算提速、真实温度反馈的
单项位置搜索验证，再根据结果决定下一项。每次只改变可解释的机制，不堆叠启发式补结果。

## 6. 本轮已执行到的结论

已完成[温度盲与温度引导对照](atplace-case1-temperature-feedback-results.md)，两组
多步能力相同，各 16 次新热查询。温度引导主点 103.221375°C / 31.536031 m，比
对照低 0.292725 K；反向距离改善 10.779%。但它仍比最冷历史参考高 0.301851 K。
两组主点的 GPU 与 CPU 位置完全相同，HBM 联合位移造成模型内温差，进一步说明
简单的 GPU 间距目标不足以指导热布局。没有追加种子或改变阈值补结果。

目前直接解决的是重复计算、遗漏历史可行冷点、对照混淆和缺少真实温度反馈的
位置搜索链。尚未解决紧约束条件下的稳定算法优势、全局探索和真实热—时序闭合。


## 7. 紧预算已经局部检验，但不是容量饱和或全局权衡证明

[后续 Chat 复核](atplace-case1-temperature-feedback-review.md)接受温度反馈结果，
并要求新预算由温度反馈实验前的固定参考定义。已据 C24 repaired 采用
L≤35.0147365608 m，两组同起点各 16 新热；[结果](atplace-case1-tight-budget-results.md)
为引导较温度盲低 0.324438 K，两组拒绝 8/3 个超预算候选。因此距离条件已限制
搜索，然而必要布线最紧利用率只有 13.2%，并非真实布线资源饱和。

一个直接单变量对子是 guided row 14→15：仅 GPU0 的 y 增加 2 mm，源 pin 总长
减少 2.816 m，而实际峰温增加 1.354464 K。固定总功率时，移动引起的 A、b 变化
可以让互连变短、热扩散变差；这比用距离推断温度更直接。它仍是当前模型内的
整体峰温变化，不是经过实测校准的某一芯粒温升或完整时序收益。

这个对子两点都满足预算；本轮与上轮的起点也不同。因此尚未量化“缩紧预算对
最优温度造成多少损失”。引导主点仍比同预算历史参考热 1.009910 K，且 2 mm
移动保留中心坐标余数类。下一项算法问题应针对可达空间与搜索效率，不将这个
差距归咎于热精度，也不通过追加种子/算子把有限结果包装成全局最优。
