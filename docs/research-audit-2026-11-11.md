## 1. Chiplet 的时序问题必须先定义接口语义

OpenSTA 处理网表、Liberty、SDC 和寄生；die 边界本身不会使 STA 失效。
关键是跨越边界时是否拥有匹配的电压、TX/RX 模型、通道模型、时钟关系和约束。
这是 [OpenSTA 文档](https://github.com/The-OpenROAD-Project/OpenSTA) 所支持的
数字时序能力，与物理接口资格验证的区别。

当前完整路径应理解为：发送寄存器 → 核心缓冲器 → TX pad → 封装通道 →
RX pad → 接收缓冲器 → 接收寄存器，同时分析 forwarded clock 的整条路径。
不能把裸核心单元直接连跨 die 的实验解释为真实 D2D。

用明确配对的边沿描述，setup slack = 最早允许的捕获到达时间 − 最晚数据到达时间
− setup − setup uncertainty；hold slack = 最早的新数据到达时间 − 对应保持边沿的
最晚时钟到达时间 − hold − hold uncertainty。源同步 data/clock 公共延迟可能抵消，
但 min/max、占空比、不同 rise/fall、接收约束和电气限制不会自动抵消。
实际边沿配对必须由 SDC、协议和展开报告共同验证。

接口类型决定可观测量：共同参考时钟分析跨 die setup/hold/skew；源同步分析
采样窗口、lane 间偏差和 data–clock 相对到达；异步 FIFO/CDC 分开验证各同步域和
同步器，协议延迟/吞吐另算。不能把通信图直接当成单周期组合时序图。

代码中需要保留且补证的边界：

- `timing.py` 固定两个 die、一条 data 和一条 clock，不是多芯粒通用 timing graph。
- `interfaces.py` 明示理想时钟、零片内线寄生、无 bump；当前控制脚真实且有来源，
  但不构成电源顺序、ESD、PHY 或信号完整性资格验证。
- `interconnect.py` 是假设截面的 R/C；`timing.py` 导出八段 RC。RC 的适用性要按
  边沿速度、传播时间、返回路径和波形误差判断，不能仅由 50 MHz 时钟断定。
- 四个 pad 活跃弧查表不等于所有核心延迟、转换时间和 setup/hold 表均在域内。
- 跨 die PVT 应分 die 赋值，并明确相关性；不能把同一 die 的每个单元任意独立选角。
- TT GPIO 与局部温度模型在方向、P/V、器件及 pad 覆盖上不同；代码正确拒绝二者合并。

[v0.6](validation-v06.md) 的孤立 pad SPICE/Liberty 不一致仍是阻断：GF 延迟
15.9–18.1%，SKY 延迟 23.4–26.6%、slew 55–62%。这既不能直接换算成 lane slack
误差界，也不能用拟合常数抹平。先统一网表/PEX、模型版本、负载参考面、阈值与
slew 定义，再比较共同与差分扰动。若异构库资料不完整，可以先建立模型完整的
同工艺双 die 对照；同工艺也需要合格 TX/RX，不能用标准单元绕过接口问题。

## 2. 热方程成立不等于真实结温已被证明

当前模型求解 `G(X) (T - T_ambient) = P(X)`。相邻有限体积单元的热导为
`A / (d1/(2 k1) + R_contact_area + d2/(2 k2))`，对流边界包含表面半单元热阻。
代码的单位、串联界面热阻、芯粒侧壁默认隔热和各向异性处理具有一致的物理解释。

仍需回答：功率是否对应目标 workload？bump/underfill 的等效导热率能否代表实际
填充率？TIM 接触和冷却条件是否有来源？热点报告位置是否对应有源层？这些输入
误差不会因为线性方程残差很小而消失。

MFIT adapter 调用锁定上游的网络组装，再用 NumPy 解同一稳态网络。这是有用的
实现交叉检查，但共享近似不会被该检查揭露。下一层应复现独立三维参考中的相同
几何、功率、材料和边界；参考求解器也要收敛。MFIT 上游提供了
[FEM 参考模型](https://github.com/AlishKanani/MFIT)，
[3D-ICE 4.0 原论文](https://arxiv.org/abs/2512.05823) 强调了垂直划分和材料异质性。
工具名称本身不能替代相同输入下的误差测量。

当前每个材料层只设一个 z 方向单元，源位于 die 层单元中心。因此还不能把所报峰温
直接称为真实 junction temperature。必须保持总功率、源层物理位置和接触面积，
补完整 XYZ 收敛；只有工作负载时间尺度要求时，再增加瞬态热容与时间步收敛。
若加入温度相关漏电，要解功率–温度固定点并检查稳定性，不能把固定功率结果沿用。

## 3. 本轮新运行的诊断

环境：Windows，Python 3.12.16、NumPy 2.5.4、SciPy 1.18.1。
最初 67 项测试有一项输入快照哈希失败：Windows 文本写入把 LF 转为 CRLF，而报告
哈希针对转换前的字节。修复为同一 UTF-8 字节序列计算哈希并写入后，67 项全部通过。
原测试已直接核验文件字节哈希，无需用更宽容的断言掩盖差异。

两个基础 CLI 峰温分别为 34.1886068 °C 与 60.7473029 °C，功率均 3 W，
`timing=not_run`。本轮未在 Windows 重新构建/运行 OpenSTA、ngspice 或完整 MFIT
验证；上述 v0.6/v0.7 时序数字来自已存仓库证据。

新诊断仅细分 interposer、bumps、TIM、lid，保持各总厚度、材料、界面和总功率，
有源 die 层不细分。输入为 `examples/low_speed_gpio.json`：

| 请求的 XY 网格 | 每个被动层 z 单元数 | 峰温 °C |
| --- | ---: | ---: |
| 24 × 16 | 1 | 60.747303 |
| 24 × 16 | 2 | 60.698411 |
| 24 × 16 | 4 | 60.685881 |
| 24 × 16 | 8 | 60.682725 |
| 48 × 32 | 1 | 60.698916 |
| 48 × 32 | 2 | 60.648187 |
| 48 × 32 | 4 | 60.634778 |
| 48 × 32 | 8 | 60.631344 |

被动层细分的 1→8 改变量约 0.0646/0.0676 K；这不是误差上界，也没有证明源层、
结温或完整 XYZ 收敛。不同 XY 网格的峰值还包含不同采样位置的影响。

另在固定原始几何上分别只激励 TX 或 RX 的功率，保留所有 die 和材料。在总温度
热点 `(1.75, 2.75) mm`，总温升 35.747303 K 分成 TX 的 25.832631 K 与 RX 的
9.914672 K，整场叠加残差约 `2.13e-14 K`。这说明该模型中的跨 die 热贡献不可忽略；
但单一布局上的贡献大小，不能证明布局变化由互热主导。峰值算子本身不满足线性叠加，
因此贡献必须在同一个总场热点位置读取。

对于这个均匀顶面对流、底面无散热的示例，守恒给出顶面平均温度
`25 + 3/(1000 × 96e-6) = 56.25 °C`。这是模型中的顶面面积平均值，非 die 峰温。
总散热能力造成的共同温升与可被布局改变的局部温升，应分开解释。

复现（已安装本项目的 Python 环境，使用新的输出文件）：

```bash
python tools/diagnose_thermal_foundation.py --output results/thermal-foundation/report.json
```

## 4. 科学问题与证据门槛

建议检验的核心问题：**有来源的接口时序和封装布线资源，在什么条件下会让热最优
布局无法获得可行路由？差分温度是否进一步改变这个边界？**

这是候选问题，不是已证实的新颖性。已有
[SI-aware placement/routing 研究](https://pure.kaist.ac.kr/en/publications/advanced-chiplet-placement-and-routing-optimization-considering-s/)
明确使用 UCIe eye-mask；因此“联合 placement/routing”或“考虑信号完整性”本身
不能宣称新贡献。后续必须做全文与开源实现核查，当前没有 SOTA 超越结果。

必须分清三个命题：

1. **约束冲突**：在同一声明设计域 A（几何/电气合法）内，加入时序约束得到 F。
   `DeltaT_constraint = min_F Tmax - min_A Tmax`。F 为空应报告不可行，不能报零；
   有限候选池的最优不能冒充全局最优。正值说明时序约束有温度代价。
2. **温度反馈的因果作用**：固定布局、路由、P/V、功率、约束，比较温度关闭/开启。
   对两个布局测量 `[S_T(B)-S_T(A)] - [S_0(B)-S_0(A)]`，分别报告 setup/hold、
   电气可行性、关键路径切换和误差。固定 TT 的正 DeltaT 并不能证明该命题。
3. **算法价值**：与 thermal-only + 足够强的 router、顺序优化、交替优化比较。
   使用相同最终评估器、候选域、资源、终止预算与失败统计；小规模用精确枚举或
   约束求解给出参照。router 未找到解不能解释为不存在解。

v0.7 的 27 布局在合法短路由下 setup 总跨度仅 0.007 ps，且各可评估路由策略
都选中 layout 26，时序温度代价为零。这支持该控制中尚无必要性；不支持 chiplet
时序永远不重要，也不支持换个权重或提高频率直到出现预期结论。

机制层研究可以在明确标注、数值自洽且参数有来源范围的抽象模型中开展，
无需等待实物签核。物理预测层必须有独立误差证据。两层的结论不能互相替代。

## 5. 下一阶段顺序

**唯一最高优先级：建立独立源同步时序参照（Source-Synchronous Timing Oracle）。**
这是对外部审核建议的采纳。先区分 SDC 语义正确与 pad/通道物理准确，不能让后者
无限期阻塞前者，也不能因已有正 slack 而默认前者已经成立。

| 项目 | 下一轮最小实验契约 |
| --- | --- |
| 固定输入 | 优先同 PDK/同供电的最小双 die 源同步接口；固定网表、库、数据/时钟路径、边沿、负载、寄生和 PVT；频率来源显式记录 |
| 语义参照 | 独立的事件时间计算，显式列出每个 launch/capture edge；逐项对照 OpenSTA full_clock_expanded，检查反相相位和实际 inverter 延迟没有重复或遗漏 |
| 控制组 | 只加 data 延迟、只加 clock 延迟、两者加同一延迟，以及有意产生 setup/hold 失败；先用固定延迟的解析例，再用合法范围内的实际 RC/负载扰动 |
| 必交输出 | launch/capture edge、data/clock arrival、required time、setup/hold slack、slew、cap、所有预期端点与未约束端点清单 |
| 放行语义层 | 事件参考与 STA 的边沿/时间一致，正负例方向正确且无漏检；误差阈值在实验前按精度声明 |
| 放行物理层 | 相同网表/PEX/模型/负载约定下的独立波形参照满足事先声明的误差预算；当前 v0.6 不满足 |
| 失败处理 | 错边沿、漏检或不明差异即暂停依赖该结果的结论；没有完整 pad 时，允许 core-level 语义基准，但标签不得升级为真实 D2D |

“加同一延迟”在固定延迟解析例中检验精确抵消；在真实 RC 实验中会同时改变波形和
接收弧，不能强制要求 slack 精确不变。物理波形检查与事件语义检查分别报告。

随后补热模型的有源层定义、XYZ 收敛与独立三维参考；在固定几何保留材料的基础上
扫描整体平移、相对间距与功率分布，区分冷却边界、自热和互热。预先声明哪些参数
来自设计、哪些只是假设，按布局差异需要的分辨率确定可接受误差。

再引入有来源的多 lane 端口顺序、共享时钟、层数、keepout 与通道容量；小域先有
精确可行性参照。不可为了制造拥塞任意缩窄通道；时序周期必须来自应用/接口要求。
若开展探索性参数扫描，应报告整个范围及无冲突区，不能事后挑选阈值做性能声明。

最后才比较优化算法。模型分辨率不足、结论随合理输入误差反转、基线仍能修复布局、
或只有数值噪声时，保留否定结论并回到机制与误差分析。
