# Case1：历史档案修复后的温度反馈父代消融

问题：有限候选池不会利用新得到的冷布局继续搜索。在相同物理模型、共同历史知识和
预算下，两组都允许新点成为父代，只测试父代选择是否使用温度；不增加交叉、代理温度、步长档位或种子。

## 先修正共同基线，0 次新热查询

Chat 指出历史 B row 40 修复后已达 102.919524°C / 60.185154 m，比上一轮局部最好点
更冷。本地独立复算确认该点；因此不能把 103.515212°C 继续当作最强已知起点。

纳入同一 Case1 名义适配器的 A/B 搜索、C 交叉、D 空隙、E 候选池、F 约束选择和
上一轮 orientation 记录的全部已求解行。重复输入按完整姿态去重，每个不同的已存储
姿态做一次已验证的 incident-net 朝向修复，保留原始与修复后的联合点。
这不是穷举方向最小化，也不反复修复新生成的状态直至收敛；不加入异边界、不同案例
或不同物理模型的历史。原有容量资源与 L0/T0 不变，全部实际 pins 重新检查。

历史缓存命中行先找到真实原热查询行，核对其完整输入 hash 和物理设计签名，再确认
命中行的命名物理边界相同，才允许复用温度。朝向不同的完整输入 hash 不冒充一致。
报告修复前后的原约束指标、恢复距离可行性的输入数、全部原/修复联合状态和零热成本。
两组使用完全相同的热响应缓存；历史修复后两项最优值只作为已知参考，不能免费
加入搜索结果或父代。不把历史修复收益记为在线反馈搜索的收益。

## 唯一方法差异

两组的初始结果档案与父代严格仅为上一轮 B repaired、D repaired 两个完整布局，
其余 448 个历史联合状态作为已知参考档案留存，225 个物理响应仅作为共享缓存。
历史点必须由本轮候选生成实际访问、通过 pins/必要布线/L0 后，才进入结果档案和父代。
全部新访问的合格完整状态都可以在两组中成为父代，不以变冷作为某组专有准入条件。

每个父代的候选都是源芯粒顺序生成的单芯粒 x/y 轴 ±2 mm，过滤载体边界、重叠和
1 mm 间隔后打乱。顺序由 `sha256([seed, full_layout_key])` 派生的随机种子确定；
同一个父代在两组中始终同序，不随方法调用随机数次数变化。

- `temperature_blind`：按完整状态 hash 排列可扩展父代，用 `Random(seed)` 均匀抽取；
  不使用温度选择、排序或决定是否新增父代。
- `temperature_guided`：选择实际峰温最低的可扩展父代，再按实际距离、完整姿态 hash
  打破平局。新增父代、邻域和准入与控制组完全相同。1e-6 K 仅用于日志标注是否比父代冷。

每步只准备实际访问到的候选；两组使用同一精确朝向修复，最终完整 pins 交给原必要
容量检查。布线/距离准入在缓存和热求解前，完整状态去重与热响应缓存分开。
任何新热几何都由同一个 FV/HiTS 名义模型实际求解；不以 GPU 间距或距离改善预测降温。

## 预算、指标与停止

单种子 2026111200，每组最多 16 次新热查询，不跨组共享本轮新响应。
每组最多 128 个访问候选、130 个父代，几何检查上限 3120（130×24），
net 长度计算上限 2703360（128×21120）。候选或预算用尽就结束，不追加样本。
历史检查、源索引初始化、全部几何检查、实际 net 长度计算、布线检查、重复点和缓存
均分别记账。两组热查询上限相等，不宣称 CPU 时间相等。

主指标仍为 min Tpeak at L≤73.840208806 m，反向指标为 min L at
Tpeak≤107.45047721858577°C；保存每次新热查询后的完整联合赢家。
分开报告原始历史→修复历史的参考改善，以及 B/D 起点→本轮实际搜索结果；
另报与修复后最强已知参考 102.919524°C 的差距，避免归因混淆。
报告实际访问候选的最小距离余量、布线/距离拒绝数及可继续扩展的父代，不能把预算耗尽
称为局部最优或完整物理可行性证明。新收益为负或为零也停止，不叠加启发式。

所有源输入、功率、封装、导热材料、边界、网格规则、HiTS 提交与上一阶段相同。
热中性方向等价仍只适用于均匀功率和各向同性材料。这是已有档案热启动的局部父代
消融，不是从头优化器排名，不证明真实 Pad 布通、RC/时序闭合或测量校准。

## 本地命令

加载 `tools/windows_env.ps1` 后，先冻结并推送，再执行：

```powershell
python tools/run_atplace_temperature_feedback.py --freeze
python tools/run_atplace_temperature_feedback.py --execute --hits ../HiTS --output results/atplace-case1-temperature-feedback-v1
python tools/run_atplace_temperature_feedback.py --verify --result results/atplace-case1-temperature-feedback-v1/result.json --output docs/evidence/atplace-case1-temperature-feedback-replay-v1.json
```

最后一项只回放保存响应，不追加热求解。历史修复、冻结及回放的耗时单独报告，
不把验证过程混入某一个方法的在线成本。
