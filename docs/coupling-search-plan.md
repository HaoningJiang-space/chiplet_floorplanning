# 寻找布局的耦合与旋钮：直接搜索的负载后悔值，以及逐芯粒功耗分配（计划，运行前冻结）

## 问题

前两次检验的结论：封装与布局可分（[封装杠杆](package-leverage-plan.md)）；负载只在少数场景改变最优布局，而且只是名义前沿内的下界（[负载杠杆](workload-leverage-plan.md)）。
本计划回答两个问题：

- **A. 负载耦合的真实大小**：在每个负载的功耗图下直接搜索，得到名义最优布局的真实后悔值，而不是前沿内的下界。场景分两组：
  - 已出现信号的声明场景，并加两个零后悔的对照；
  - 按公开测量校准过的 LLM 推理阶段。
- **B. 旋钮**：芯片在运行时可以逐芯粒调节功耗（DVFS、睿频）。从第一性原理看，
  - 若所有计算芯粒按同一比例降频，可持续性能完全由峰温决定，最冷布局就是性能最好的布局，没有耦合；
  - 只有逐芯粒分配功耗、并且各类芯粒的温度上限不同（存储通常比逻辑低约 10 K）时，最冷布局才可能不是性能最好的布局。
  
  所以 B 问：**以"逐芯粒功耗可调时的最大可持续算力"为指标，按峰温选出的最冷布局损失多少？**

## A. 直接搜索（冻结）

- 方法：lp_epsilon（温度方向最强），1000 次 FV，单种子 2026111401，共同起点 48 个随机加 48 个长度下降，batch 48。
  长度上限为名义前沿最短长度的 1.25 倍，与前两次检验相同。每例在名义功耗图下搜索一次，每个目标场景下各搜索一次，起点相同。
- 目标：
  - **声明组**：Case10 cpu_idle、Case10 compute_half、Case3 even_idle、Case9 gpu_idle、Case4 even_idle（budget 族）；
  - **对照**：Case5 even_idle、Case6 gpu_idle（前沿内后悔为 0）；
  - **LLM 组**：Case1/2/4/6/9 × {预填充，解码 HBM 满，解码 HBM 半}。预填充与解码时，存储取声明活动，其他芯粒取名义，
    全部计算芯粒取同一活动，使整卡功耗等于上表比例（限制在 0.2–1.0，不睿频）。
- 后悔值的取法：
  - N = 名义功耗下、上限内最冷的布局，候选为名义前沿加名义搜索结果；
  - S = 场景功耗下、上限内最冷的布局，候选为名义前沿、N 和场景搜索结果，全部按场景功耗求解；
  - 后悔值 = T_s(N) − T_s(S)；反向代价 = T_nom(S) − T_nom(N)。两者都大，说明同一个布局无法同时服务两种负载。
- 判定（每组分别给出，对照不计）：至少 3 个目标后悔值 ≥ 1.0 K 为"值得做"；有 1–2 个为"不确定"；没有为"未发现"。

## B. 逐芯粒功耗旋钮（冻结）

- 评估集：十例名义前沿全部 1340 个布局。每个布局用单位功耗响应叠加（每个芯粒 1 W 各解一次）；
  叠加出的名义峰温须与冻结前沿一致（≤1e-6 K）。
- 每个布局：
  - 计算芯粒的活动 x_i 可在 0.2–1.5 之间取值，其余芯粒保持名义功耗；
  - 约束：每个芯粒内部的每个功耗层网格都不超过该芯粒类型的温度上限；
  - 最大化 Σ 名义功耗_i · x_i^(1/3)，用 8 个折点的分段线性加 LP 精确求解。
  - 同时计算"统一降频"的结果：所有计算芯粒取同一个 x。
- 每例在 1.25×Lmin 上限内比较：
  - 按名义峰温选出的最冷布局 C；
  - 算力最大的布局 B；
  - **损失** = 1 − 算力(C)/算力(B)；
  - **旋钮价值** = C 上逐芯粒分配相对统一降频多出的算力；
  - 名义峰温排序与算力排序的 Spearman 相关。
- 判定（以主温度上限为准，较冷一档另报）：至少 3 例损失 ≥ 3% 为"值得做"；全部 < 1% 为"退化"；其余"不确定"。
  无可行分配（例如固定功耗的芯粒本身已超限）的例子不计入；所有例子都无可比数据时判"无数据"，不判"退化"。
  最冷布局不可行而上限内另有可行布局时，损失记为 100%（布局带来的可行性改善），计入判定。
  排序相关用平均秩的 Spearman；任一序列为常数时记为未定义。

## 运行前估计

- **A**：
  - 声明组：前沿内下界为 3.14、1.73、1.62、0.62、0.60 K，直接搜索只会更大或持平，所以至少 3 个 ≥ 1.0 K 的可能性较高，预测"值得做"。
    对照可能从 0 变成正值，因为场景搜索也会找到前沿外的布局。
  - LLM 组：主要改变计算与存储的比例，和前沿内 memory_idle、compute_half 相近；这两者在 Case1/2/4/6/9 上后悔为 0，预测"未发现"或"不确定"。
- **B**：最冷布局优化的是名义功耗比例下的全局峰值，不管峰值落在哪类芯粒，也不管存储的上限更低。
  有 HBM/DRAM 紧挨大功耗 GPU 或 CPU 的例子（Case1/4/6/9）可能由存储上限决定降频，此时损失可能 ≥ 3%；
  只有一类计算芯粒、且没有低上限芯粒的例子（Case8 只有 CPU1 和 Analog）损失预计 < 1%。预测"不确定"或"值得做"。
  旋钮价值（逐芯粒对统一降频）预计 5–20%。

## 局限

- A 只有单种子，而且后悔值依赖两次搜索各自的质量；由于 N 与 S 的候选集都包含名义前沿，后悔值不会因为场景搜索更弱而变成负数。
- B 的候选仍来自名义前沿，算力最大的布局可能在前沿之外，所以损失是下界。
- 稳态分析不含瞬态与调度。
- 性能模型、温度上限和芯粒功耗都是声明值。
