# 工业案例：H100 类与 4 GPU + 16 HBM 类（计划，运行前冻结）

依据：[产品数据核查](industrial-benchmark-data.md)、[H100 实测功耗](industrial-benchmark-data.md#h100-实测功耗校准点同日子代理通读-7-篇论文原文标图的数值读自图中)、[分阶段功耗筛查](phase-power-plan.md)（结论：预填充始终是起约束作用的阶段，所以只用预填充功耗）。

## 问题

1. **找回**：方法在不知道产品排法的情况下，能否找到与产品排法一样好（或更好）的布局？
2. **改进与折中**：在同一模型、同一约束下，产品排法离"线长—温度"前沿有多远？中介层若有余量，用多少线长能换多少温度？

## 共同设定（声明的假设）

- 芯粒间距 0.2 mm（IHP Open-ADK ASM.b = 200 µm）；芯粒内部均匀发热；环境 45 °C；FV 64 网格。
- **冷却标定**：调散热器顶面换热系数 h，使人工布局的 GPU 峰温等于 85 °C（与分阶段筛查的主设定相同）；每个案例、每种中介层各标定一次，之后方法与人工布局共用这个 h。
- **网表**：按接口带宽合成，每 20 GB/s 一条两端线；同一接口的线共用两端的引脚位置。
  - 引脚位置：HBM 接口在 GPU 的长边上（每个 HBM 一个槽位，与人工布局中该 HBM 的中心对齐）；HBM 一侧在其一条边的中点；GPU 之间与 GPU 到 IO 的接口在 GPU 短边中点。
  - 这样人工布局中 HBM 连线长度就是间距 0.2 mm，与产品中 HBM 紧贴 GPU 一致。
- **封装扩展**：均热板边长取 max(100 mm, 中介层长边 + 20 mm)，不超过 200 mm 的封装。中介层不超过 100 mm 的案例（含 ATPlace 的 10 个例子）与原来完全相同。
- **两种中介层**：
  - **紧**：G1 用 H100 中介层的估计尺寸 50 × 48 mm；G2 没有尺寸数据，用人工布局外框每边各留 0.8 mm（G1 横向余量即为每边 0.8 mm）；
  - **松**：紧中介层的长宽各放大 15%，人工布局居中。

## 案例

**G1：H100 类**（与分阶段筛查相同的芯粒与人工布局）
- GPU 26.0 × 31.3 mm，540 W；6 个 HBM3（11 × 11 mm），5 个工作各 22 W，1 个假片 0 W，无连线。
- HBM3 每个 0.67 TB/s → 34 条线；GPU 左长边 3 个槽位、右长边 2 个。
- 人工布局：GPU 居中，左右各一列 3 个 HBM（产品照片）。中介层紧 50.0 × 48.0 mm，松 57.5 × 55.2 mm。

**G2：4 GPU + 16 HBM + 2 IO 类**（Rubin Ultra 类，GTC 2025 发布的结构；封装细节为声明的假设）
- 4 个 GPU，同 G1 尺寸，各 750 W；16 个 HBM4E（11 × 11 mm），各 25 W；2 个 IO 芯粒（26 × 12 mm），各 60 W；共 3,520 W。
  - 约 3.6 kW 的说法未核实；HBM4 的功率说法不一致（18–20 W 对 75 W），取 25 W。
- 连线：
  - HBM4E 每个 2 TB/s（2048 位）→ 100 条，每个 GPU 两条长边各 2 个槽位；
  - 相邻 GPU 之间 10 TB/s（NV-HBI 口径）→ 500 条；
  - 每个 IO 连最近的两个 GPU，各 1.8 TB/s → 90 条。
- 人工布局：4 个 GPU 排成一列，短边相对；两端各一个 IO；每个 GPU 两侧各 2 个 HBM。
  - 紧中介层 50.0 × 151.8 mm；松 57.5 × 174.6 mm。

## 方法与运行

- relation_space：Gurobi 300 s，1000 次 FV，batch 48，随机起点与线长下降起点各 48，间隙 0.2 mm，16 个进程，**种子 1，只跑一次**；moe-server。
- 方法不知道人工布局（不放进起点集）。

## 指标（每个案例、每种中介层）

- 人工布局：线长 L_h、最高芯粒峰温 T_h，另报 GPU 与 HBM 各自的峰温。
- ΔT = T_h − （前沿中线长 ≤ L_h 的布局的最低峰温）；ΔL = 1 − （前沿中峰温 ≤ T_h 的最短线长）/ L_h。
- 另报：线长 ≤ 1.1 L_h、≤ 1.25 L_h 时的最低峰温；前沿最短线长与 L_h 之比；这些布局的 HBM 最长连线。

## 判定（运行前写定）

- **优于人工**：ΔT ≥ 1 K 或 ΔL ≥ 10%（与 ATPlace 比较相同的裕量）；
- **找回人工**：不满足上一条，但前沿中有一个布局线长 ≤ 1.01 L_h、峰温 ≤ T_h + 0.5 K；
- 否则为**不如人工**。

"不如人工"直接说明方法在工业约束下有缺陷，如实报告。

## 运行前估计

- G1 紧：空间几乎只容得下产品排法，预计"找回"。
- G1 松：可以把 HBM 稍微拉开，但 HBM 连线变长；预计"找回"，ΔT < 1 K。
- G2 紧：GPU 只能换顺序和朝向，预计"找回"。
- G2 松：GPU 之间可以拉开约 23 mm 的总余量，用 GPU 间连线换温度，预计"优于人工"（ΔT 几 K，线长代价大）。

## 局限

- 芯粒长宽、中介层尺寸、功率拆分、带宽与引脚位置都是声明的假设；
- 一个种子；只用预填充功耗；
- G2 在产品中可能用两块中介层，这里按一块处理；
- 温度上限不区分 GPU 与 HBM（只用最高芯粒峰温），GPU 与 HBM 各自的峰温另报。
