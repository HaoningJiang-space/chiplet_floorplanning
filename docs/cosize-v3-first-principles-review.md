# cosize-v3：当前瓶颈与有界改进顺序

2026-11-17。会话起始 fetch origin 成功，分析版本为
`959f8785db4b24513933b2e539ecfbb272b166c8`，当时本地 main 与 origin/main 一致且工作区干净。
这是实现复核和下一步建议，不修改 [v3 冻结协议](cosize-v3-plan.md)，不宣称 v3 已有正式比较结果。

## 1. 当前问题是什么

按仓库 v2 处置记录，已完成的 16 个 cosize 任务只有 6 个返回设计，另外 10 个在联合尺寸 MILP
中超时而没有 incumbent。该统计来自已提交的运行记录，本轮没有重新访问运行机器或读取原始任务文件。
因此首先应提高有限时间内产生可认证布局的能力，而不是继续增加热代理变量。
v3 的固定载板子问题、已知参照布局和 FV 认证方向合理，但实现仍有两个搜索中断点。

问题可写为：

\[
\min_{W,H,x} C(W,H),\quad
x\in\mathcal L(W,H),\quad L_{pin}(x)\le L_{ref},\quad
J(W,H,x)=\max_i[T_i^{FV}(W,H,x)-T_{ref}]\le0.
\]

这里 `T_ref` 是参照布局峰温，当前 CLI 将它赋给所有芯粒；达到它表示热质量不劣于参照，
并不等于满足逻辑/存储的器件绝对温限。`L_pin` 是逐引脚曼哈顿和，仍不是布线完成后的长度或时序。
保留这个相对质量问题即可，不要在这一阶段同时加入模式调度、绝对温限和新封装材料。

固定长宽比时，默认硅成本模型随尺度非减，有离散场数和基板档位跳变。
但“有限时间的搜索有没有找到达标布局”不是单调的可行性判定器。
此外，变载板会改变 FV 导热矩阵 G；固定 G 下的线性、无源性不推出跨尺寸温度单调。
所以成本单调不能为当前失败即剪枝的面积二分提供充分依据。

## 2. 已确认的实现问题

证据为本机四芯粒控制及明确标注的超时注入，见
[controls](evidence/cosize-v3-review-959f878.json)。没有据此推断正式 17 个组合的胜负。

### A. 基线没有复核锚点，且缩尺寸后丢掉锚点

`tools/run_cosize.py:68` 直接填写 `thermal=0`、`length_m=length_m`、每芯粒超温全零；
没有在此路径调用 FV 或核对真实长度。主方法 `anchored` 则会重算和拒绝复现不一致。

实际 FV 控制：峰温 59.1888586311 °C，故意将参照温限设低 0.5 K。
`fixed_aspect` 返回 `certified=True, j_k=0, fv_solves=0`；主方法返回 `reproduction_mismatch`。
这是输入不匹配时的真实错误，并不证明当前存档参照已经不匹配。
即使标量峰温正确，所有芯粒的超温也不能用全零代替测量值。

随后基线在每个新尺寸用 `run_front(..., extra_starts=[])` 从头搜索；主方法却用本族前一认证布局
缩放并合法化。这会使紧线长预算下的比较同时混入初始化差异。

**最小修复：** 共用一次锚点复核路径，保存真实逐芯粒 J 和长度、核对几何，计入预算；不匹配时所有
方法相同地退出。基线每个新尺寸也通过 `fit_into` 传入上一认证布局。步零必须保留原尺寸，不能把
非网格原尺寸向上取整后的载板直接当作同一个已复核锚点。

### B. 超时会丢掉合法起点，并放弃整个形状族

`fixed_carrier` 只返回求解器产物；即使传入合法、线长达标的 start，MILP 无 incumbent 时仍返回 None。
`family` 在第一次认证失败时直接 break；后续失败则上移 low。
这把超时、一个候选不达标、几何/线长被证明不可行合并成同一个搜索动作。
控制流注入 `time_limit` 后，五步族搜索只试一次，FV 次数为零。

**最小修复：** 缩放/合法化的起点是独立候选，先做实际长度检查，交给有预算上限的 FV 局部修复；
保留所有已认证候选。MILP 负责提供新的拓扑候选，不能用 None 覆盖已有候选。
需要继续区分 `certified`、`not_found`（含超时和认证失败）、`proven_infeasible`。
只有针对必要几何/线长约束的可靠不可行证明，才有资格排除相应范围；不能把一个代理布局热失败
解释为该载板不存在真实可行布局。

### C. v3 的前置 FV 重新绕过了小预算

`anchored` 在检查剩余预算之前执行锚点 FV 和代理校准。实测预算 0、blind 模式仍执行 1 次 FV。
这是 v3 新路径的回归，不能引用旧 `cosize` 的预算测试说明它已经受到保护。
正式 1000 次设置未由这个小控制证明超预算；应在复核/校准前统一扣预算，预算不足时保留明确停止状态。

## 3. 推荐的搜索调整：先连续改进，再按成本边界补充候选

不建议回到联合尺寸大 MILP，也不建议立即增加 K、种子或再做一轮热标定。
优先复用现有 `fit_into`、`certify`、固定载板 MILP 和 `run_front`：

1. **从认证解逐步缩尺寸。** 原长宽比先走小幅收缩；其他长宽比从邻近已认证形状逐步变化。
   先试保留拓扑的局部修复，在热/线长预算内获得真正的候选，再将 MILP 作为换拓扑的补充。
   几何合法化并不保证长度达标，更不保证温度达标，三项必须分别检查。
2. **取消首次失败即放弃整族。** 最初可直接用每族 3–5 个预定尺度点，按邻近关系传递已认证布局；
   对找到改善的区间细化。未找到解只记录失败点，在有限预算内继续其他尺度。
   这是一种有限候选搜索，不应报告全局最小尺寸或把失败点当作可行域边界。
3. **优先采样成本变化处。** 在当前成本模型的曝光场数切换、单场 26 × 33 mm 边界及基板档位附近
   保留网格候选；按 `interposer_cost` 的实际输出排序。目标是美元成本，面积略小但仍停在同一高成本
   档位的候选未必比另一长宽比的候选重要。不为此引入额外制造模型。
4. **约束总求解时间。** 当前每次 `fixed_carrier` 最多四轮切割、每轮轴向和 K8 各一份时间：
   `milp_s=60` 意味着一个尺寸最多约 480 s 的 MILP，而非 120 s；五步可达 40 分钟/族，尚未含 FV。
   给一个尺寸设总剩余时限，轴向、K8、切割共享它。保留实际 FV、MILP 时间和返回状态即可。

上面是待实现建议，不能将它们写成已经冻结或已经验证有效的算法。若采纳，在试跑前更新协议版本，
不把旧 v3 产物与改过候选搜索的新产物混在一起。

## 4. 用最少的比较回答贡献在哪里

`cosize` 对 `fixed_aspect` 同时改变长宽比自由度、内层算法和新尺寸的初始化，单凭胜负不能断言热代理
是收益来源。先给双方同样的连续初始化，再在原定两个试跑案例加入一个有界对照：
**同样的形状/尺寸候选，内层换成已有 relation_space**。这无需先扩成完整消融活动。

- 若多长宽比的两种内层都比 fixed_aspect 好，主要贡献是尺寸/形状自由度。
- 若代理内层在相同候选、起点及资源预算下更好，才有证据支持代理搜索的额外价值。
- 若只是比原载板便宜而没有胜过修正后的搜索基线，应报告成本压缩可行，不宣称算法领先。

FV 上限相同不能单独解释 v2 这种 MILP 主导的耗时；试跑需同时固定 CPU 配额和总时限，保存已用资源。
`--workers` 目前没有传到 `anchored`，实际使用其默认 8 进程 × 2 线程；正式比较前应让配置和记录一致。

汇总器还需区分运行进度与最终结论：现 `cosize_compare.verdict` 在 17 组合中仅有 7 胜、其余文件缺失时
就可输出 effective。冻结分母仍取 17；加“是否完成/可配对”的状态，不在运行中提前宣布正式结果。
同时检查协议、输入/锚点哈希与参照上限一致，防止 v2/v3 或不同参照被文件名误配对。
这是当前确有多个版本共存带来的具体比较问题，不需要扩展成通用实验管理系统。

## 5. 下一步的有界顺序

1. 先修复共用锚点复核、连续初始化、保留候选、失败状态和前置预算。补对应的小控制，运行必要测试。
2. 仍用已经选好的 **Case1 atp_cool、Case6 atp_wl、一个种子**，不另挑容易赢的案例。
   先看新载板上是否产生实际认证候选、失败发生在哪里、时间用在哪里；同时保留原载板锚点作为回退。
3. 上述试跑能完成搜索且比较口径正确后，再按同一修订协议完成冻结的 17 组合。原来的 5% 单组合
   成本胜负门槛和总体判定门槛不因观察结果而修改。试跑本身不承担总体有效性的判定。
4. 若紧线长案例仍停在锚点，优先尝试保留 ATPlace 拓扑的局部变形、逐引脚预算约束下的布局修复；
   不把“更长 MILP 时限”当作唯一解法。若最终只是平局，如实接受该范围内没有成本改进。

本轮没有改生产代码、启动/停止远端实验或重跑标定。只执行上述小控制；文档/证据更新不重复完整
测试集和 CLI。热模型仍为声明的 FV 研究模型，外部物理验证与真实时序证据没有新增。
