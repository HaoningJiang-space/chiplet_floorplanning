**从这张表读出的结论：**
1. **没有哪一种机制始终最好；最好的机制随规模变化。**

## 2. 下一版设计草案：在机制和形状上逐轮淘汰（successive halving）

**目标：** 只用一份 FV 预算（1000 次）和相同的墙钟时间预算，自动把预算集中到对当前例子有效的机制和形状上。

**臂（arm）：** 每个臂是一种机制加一种形状设定，都从同一个已复核的锚点出发：
- (a) **联合尺寸 MILP**（v2 的形式：宽度档位 × 连续高度，只看线长或带代理）。它在小例子上最好，大例子上会超时没有解。
- (b) 每个长宽比族各一个**映射修复加最小线长 MILP 生成器**的臂（v3.2 blind 的形式）。
- (c) 每个长宽比族各一个 **relation_space** 的臂（固定载板，按面积二分）；其中**原长宽比族这一臂就是 fixed_aspect 本身**。

**逐轮分配：**
- 第 0 轮：每臂分到少量 FV（如 25 次）和少量 MILP 时间，记录各臂的最低认证成本。还没有认证结果的臂，按它的下界或"未知"排序。
- 每一轮保留前一半的臂，下一轮每臂的预算加倍，并从该臂上一轮最好的认证布局继续，不从头开始。
- 共 4–5 轮，总 FV 不超过 1000。

**为什么这样能修掉此前的问题：**
- 所有形状用**同一种**强内层机制竞争，不会再出现 v5a 那种"用弱的、带形状偏好的方法做筛选"。
- 每个臂都在自己的最小认证面积附近继续下探，区间由这个臂自己的结果决定，不会再出现 v5a 那种过窄的精搜区间。
- 联合尺寸 MILP 在大例子上第 0 轮就会因为没有解而被淘汰，不会再像 v2 那样空耗；在小例子上它会留下来。
- fixed_aspect 是候选臂之一，所以除了预算被分走的那部分，方法不会系统性地比它差。代价是：如果 fixed_aspect 正好是最好的臂，它分到的预算比单独运行时少。

**风险与需要事先回答的问题（请审阅）：**
1. MILP 臂消耗的是墙钟时间而不是 FV，两种资源怎么折算？草案：所有臂共用一个墙钟上限，FV 预算单独计算。
2. 第 0 轮每臂约 25 次 FV，对 relation_space 来说很少（它需要初始化）。是否把 relation_space 臂的第 0 轮改为"映射修复 + 少量 SLP"，从第 1 轮起再用 relation_space？这又会回到 v5a 的"两种强度"问题。
3. 臂太多会把预算摊薄：机制 3 种 × 族 8 个 ≈ 17 个臂。草案只对 (b)、(c) 开长宽比族，(a) 只开一个臂。
4. 正式比较对手仍是重跑的 fixed_aspect，判定门槛不变（单组合 5%，总体胜 ≥ 40% 且负 ≤ 10%）。试跑组合与门槛和 v4 / v5 相同。
