# ATPlace2.5D 基线：运行环境与 Case1 初步对比（2026-11-16）

目的：为方法论文做正面比较。我们的方法（拓扑线性规划加精确 FV 热求解）与 ATPlace2.5D（ICCAD'24，开源版 `fe3dbfd`）放在同一热模型、同一线长下比较。

## 运行环境

- 机器：moe-server（hpclab03，104 核），经 poweric 跳板机登录。Gurobi 学术许可证绑定在这台机器上，所以 ATPlace 在这里运行；eex005 上没有许可证。
- 目录：`/data/ziheng/haoning/ATPlace_pub`。从 eex005 原样复制，提交 `fe3dbfd`，与我们导入的案例同源。
- conda 环境 `atplace`：Python 3.9，torch 2.0.1（CPU），gurobipy 10.0.3，pulp 3.3.1，其余按 requirements.txt。
- ATSim：PKU-IDEA/ATSim_pub 提交 `4b4ff81`，SHA-256 `5350807b…29eac`，与仓库 README 一致。
- 参数：各例 `WL-driven.json`、`Thermal-aware.json` 的默认值；随机种子 1000；`num_threads` 64。

## Case1 结果

ATPlace 的流程：
1. 线长模式布局：11 s；
2. 热模型训练：用 ATSim 生成标签，约 6 分钟，测试集平均误差 0.60 °C（5 个布局）；
3. 热感知布局：40 s。

| 布局 | 线长（我们复算） | ATSim 峰温 | 我们的 FV 峰温 |
| --- | --- | --- | --- |
| 线长模式 | 11.967 m（ATPlace 报 11.967224） | 106.52 °C | 112.09 °C |
| 热感知模式 | 27.348 m（ATPlace 报 27.347662） | 99.53 °C | 104.98 °C |

核对：
- 旋转方向与我们一致：同号时线长相符，差别来自单精度坐标；
- `(x, y)` 是芯粒中心；
- 两个布局在间隙 0 下都合法。

与我们冻结前沿的比较（我们的 FV 模型；前沿用了 12000 次 FV）：
- 热感知点：同线长下，我们的前沿最冷为 103.27 °C，**凉 1.72 K**；同温度下，前沿只需 18.31 m，**短 9.04 m（−33%）**；
- 线长点：ATPlace 的 11.97 m 短于我们前沿的最短 12.28 m。在纯线长上 ATPlace 更好（它用整数规划初始化）。

## 还不能下结论的原因

1. 热模型不同：
   - ATPlace 优化的是 ATSim 温度：均热板边长为 W+H = 84 mm，散热器 168 mm，对流热阻 0.01 K/W；
   - 我们是 TAP 族 FV：100 mm 均热板，200 mm 散热器。
   在我们的模型里比较，对 ATPlace 不利。需要反过来，用 ATSim 评估我们的前沿。
2. 算力不同：我们的前沿用了 12000 次 FV（约 50 分钟单核），ATPlace 共约 7 分钟。需要在相同时间或相同 FV 次数下比较。
3. ATPlace 每次只给一个点。要得到它的取舍曲线，需要扫描它的热权重或温度阈值。
4. 目前只有 Case1、单种子。

下一步需要一份冻结的比较计划：十例、两种热模型双向评估、等算力条件、扫描 ATPlace 参数。
